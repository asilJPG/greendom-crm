# Облако склада (Vercel + Neon)

Сайт и API склада теплицы. Моноблок на складе присылает свои операции в `/api/ingest`, сайт показывает остатки и отчёты и сам ведёт операции и финансы.

## Что умеет сайт
- **Вход** по паролю (пароль определяет пользователя и роль) или по Face ID / Touch ID (WebAuthn, `api/passkey.js`). 5 неверных попыток подряд блокируют вход на 15 минут.
- **Роли:**
  - `admin` ведёт всё: пользователей, справочники, финансы, правки и отмены;
  - `director` только смотрит остатки, отчёты и финансы;
  - `keeper` (складовщик) вносит приход, продажу и списание, может быстро добавить покупателя.
- **Складские операции** (`api/command.js`, `lib/warehouse.js`):
  - приход, продажа и списание с сайта сразу записываются в облако строками `device='web'`, моноблок получает их зеркалом в ответе `/api/ingest`;
  - правка или отмена записи моноблока ставится в очередь команд для этого моноблока. Если моноблок не выходил на связь больше 24 ч, изменение применяется прямо в облаке;
  - остаток проверяется под блокировкой, повтор с тем же `request_id` не применяется дважды.
- **Финансы** (`api/report.js` → `lib/expenses.js`, `reconcile.js`, `investments.js`):
  - акты расхода со строками, оплаты контрагентам и от них, акт сверки, инвестиции и окупаемость;
  - каждая денежная запись выполняется одной транзакцией: ключ `request_id`, документ и строка `audit_log` пишутся вместе.
- **Справочники** (`lib/refs.js`): сорта (переименование доходит до моноблоков через алиасы) и контрагенты.
- **Telegram:** уведомления о приходах и продажах в группу (необязательно).
- **Журнал действий** `audit_log` виден администратору.

## Переменные окружения (Vercel → Settings → Environment Variables)
Значения храните только в настройках Vercel и никогда не записывайте в файлы репозитория.

| Переменная | Обязательна | Что это |
|---|---|---|
| `DATABASE_URL` | да | строка подключения к Neon Postgres |
| `SESSION_SECRET` | да | подпись сессий и ключ шифрования сохранённых паролей (≥ 16 символов; если его сменить, все выйдут из системы) |
| `INGEST_TOKEN` | да | ключ моноблока для `/api/ingest` (≥ 16 символов, тот же, что в `sync.token` моноблока) |
| `SETUP_KEY` | для первого запуска | одноразовый ключ `POST /api/setup`: создаёт первого администратора, пока в базе нет пользователей (≥ 16 символов) |
| `TG_BOT_TOKEN`, `TG_CHAT_ID` | нет | бот и чат(ы) для уведомлений; несколько чатов указываются через запятую |
| `TG_THREAD_ID` | нет | тема в группе-форуме |
| `TG_BUDGET_MS` | нет | сколько времени (в мс) приёмник тратит на отправку уведомлений, по умолчанию 7000 |
| `TZ_NAME` | нет | часовой пояс для «сегодня», по умолчанию `Asia/Tashkent` |

Схема базы создаётся и обновляется сама при первом запросе (`lib/db.js`, `lib/schema_*.js`).

## Структура
- `api/*.js`: serverless-функции Vercel. Сейчас их 11, а лимит тарифа Hobby — **12**, поэтому новые файлы в `api/` не добавляйте. Новые разделы подключайте через `?resource=` в существующих функциях (так устроены `report.js` и `status.js`).
- `lib/*.js`: доменная логика, база, вход, Telegram.
- `public/`: сайт (SPA, маршруты описаны в `vercel.json`).
- `test/`: проверки на PGlite (локальный Postgres, без сети) и локальный стенд.

## Локально
```
npm install
npm test                 # все проверки (test/*.test.js) на PGlite
node test/devserver.js   # стенд http://localhost:3100: те же обработчики поверх PGlite в памяти, ключи тестовые
```
На стенде первого администратора создаёт `POST /api/setup` с ключом `SETUP_KEY` из `test/devserver.js`.

## Развёртывание
Изменения в ветке `main` на GitHub Vercel публикует автоматически. Перед пушем `npm test` должен пройти полностью. Моноблок настраивается так: `sync.url` = `https://<домен>/api/ingest`, `sync.token` = `INGEST_TOKEN`.
